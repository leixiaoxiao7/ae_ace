# U-Net 重建蒙娜丽莎：机制图解（老外婆版）

> 对应脚本：`example_01.py`
> 一句话总纲：**先眯眼记大局（编码器 + bottleneck），再睁眼照原图补细节（解码器 + 跳跃连接）。**

## 一个故事讲完整个流程：老师傅修补古画

师傅接到任务：照着蒙娜丽莎原作，重画一幅一模一样的。

### 第一步：眯眼看画（编码器，卷积 + pooling ×3）

师傅眯起眼睛看一次——细节没了，只剩大块明暗；再眯一次——只剩"中间一个人、背景两片风景"；眯第三次——只剩整体感觉："暖色调，人坐正中，光从左上来。"

三次眯眼 = 三个粗细层级，像地图软件的三档缩放：

| 眯眼次数 | 相当于地图 | 还能看清什么 | 网络里对应 | 特征图大小 |
|---|---|---|---|---|
| 第 1 次 | 街道级 | 边缘、色块、纹理（"这里有一道亮边"） | c1 → p1 | 256→128 |
| 第 2 次 | 城市级 | 局部部件（眼睛形状、嘴角弧度、衣领走向） | c2 → p2 | 128→64 |
| 第 3 次 | 国家级 | 全局布局（人坐正中、光从左来） | c3 → p3 | 64→32 |

要点：

- **每一层看到的都是整张画**，只是粗细不同——不是拆成三种东西，而是同一内容的三个抽象等级：细节 → 部件 → 全局。
- **决定看粗还是看细的是特征图大小（分辨率），不是 filters 数量**。浅层在全分辨率上工作，只能看到细节；深层在缩小的图上，只能看到大局。
- **图越小，备注反而越多**（filters 64→128→256）：细节 pattern 种类少（边、色块，几十种说完），全局概念组合爆炸（"鼻梁连着颧骨的光影"有成千上万种），需要更多通道来记。

### 第二步：写小抄，读两遍（bottleneck，32×32×512）

眯到最后，师傅把整体感觉写成一张小抄——不是一句话，而是 **512 条备注**：肤色多暖、光从哪边来、衣服什么调子……备注越全，重画时大局越不歪。

而且师傅**把小抄读了两遍**（代码里连续两行 `conv_bn`），心里过两遍"这画整体该怎么组织"，而不是扫一眼就动笔。

为什么非要把图缩到这么小？因为只有这样，师傅才没法死抠某一缕头发，**被迫先想清楚整张画长什么样**。大局先对，才不会画出"眼睛很精致但长歪了"的笑话。

### 第三步：对照原照片修补（解码器，放大 + 跳跃连接 ×3）

开始往回画。每把画放大一步，师傅就把**当初眯眼之前拍下的清晰局部照片**钉在画板边上，照着补细节：发丝、嘴角、衣褶——全照着原照片描，不靠猜。

三次放大，对应三个层级逐一补回：先按小抄搭全局架子，再补部件，最后补纹理。

### 收尾：调色交画（sigmoid 输出层）

最后把所有线索调成红绿蓝三种颜色，每种颜色深浅限制在 0~1——和原图同一量纲，交画。

## 完整流程图

```
原图 256×256
   │  卷积找花纹（放大镜滑全图，filters=64）
   ▼
眯眼① 128×128 ────────────拍照留底①──┐
   │  卷积（filters=128）             │
   ▼                                 │
眯眼② 64×64 ─────────────拍照留底②──┤ 跳跃连接
   │  卷积（filters=256）             │（Concatenate：
   ▼                                 │  修补时对照原照片）
眯眼③ 32×32 ─────────────拍照留底③──┘
   │
   ▼
小抄 32×32×512（读两遍：conv_bn ×2）
   │
   ▼ 放大③ + 对照照片③ + 卷积修补（filters=256）
  64×64
   ▼ 放大② + 对照照片② + 卷积修补（filters=128）
 128×128
   ▼ 放大① + 对照照片① + 卷积修补（filters=64）
 256×256
   ▼ sigmoid 调色（0~1）
 重建图
```

## 每个角色一句话（速查表）

| 层 | 通俗理解 | 真正的作用 |
|---|---|---|
| `Input` | 收件台 | 规定输入形状 256×256×3 |
| `Conv2D`(3×3) | 放大镜滑全图找花纹 | **学习"什么特征有用"**；filters=放大镜个数 |
| `BatchNormalization` | 每道工序后校准分量 | 稳住数值，防训练塌缩 |
| `ReLU` | 负数归零，正数放行 | 引入非线性，才能学复杂模式 |
| `MaxPooling2D` | 眯眼：四格留最显眼的 | **保强弃弱、压缩空间**；代价是丢掉精确位置 |
| `UpSampling2D` | 平滑放大（bilinear） | 解码时逐步恢复原尺寸 |
| `Concatenate` | 钉在画板边的原照片 | 跳跃连接：把 pooling 丢掉的位置信息救回来 |
| `Conv2D`(3, sigmoid) | 收尾调色 | 输出 0~1 的 RGB 像素 |

## 三个最容易搞混的点

1. **"眯眼=浓缩出有用特征？"——对了一半。**
   判断"什么有用"的是**卷积**（卷积核是学出来的）；pooling 本身很笨，只是无脑地"每四格留最大"。它记住"这一带有花纹"，忘掉"花纹在门牌几号"。被忘掉的精细位置，正是模糊的根源，也是跳跃连接要救的东西。

2. **"filters 小=专注细节？"——顺序反了。**
   位置（分辨率）决定看粗看细：浅层在全分辨率上只能看细节，深层在小图上只能看大局。filters 数量跟着"这一层有多少种东西要表达"走：细节种类少→64 够；全局概念多→512 才够。

3. **"bottleneck 是压缩点？"——在这个 U-Net 里不是。**
   32×32×512 的数值总量比原图还大。它压缩的是**空间**（只有 32×32 个位置，逼网络以粗粒度思考全局），不是信息量。细节由跳跃连接绕路保送，bottleneck 只管全局结构——两者分工，才有近无损的重建。

## 三句话背下来

1. 卷积提炼特征（学什么有用），pooling 浓缩空间（留最强、弃位置），跳跃连接把被弃的位置救回来。
2. 编码器从"看得清"走到"看得懂"（细节→部件→全局），解码器倒着走回来，边放大边对照原照片修补。
3. 大局不歪（bottleneck 小抄），细节不丢（跳跃连接），画出来就像原作了。
